# Proteindle

A daily guessing game for human proteins. Guess one, and every column tells
you something about how close you were.

Static site, no backend, no build step. The whole game is three files in
`web/` plus a JSON database generated by the pipeline.

---

## Quick start

```bash
# 1. try it immediately on six hand-written proteins
python pipeline/make_fixture.py --run
python serve.py

# 2. when you want the real thing (~300 MB of downloads, one-off)
python pipeline/download.py
python pipeline/build.py
python pipeline/entropy.py     # check the columns actually carry information
python serve.py
```

Python 3.8+ and nothing else. No pip install — the pipeline is pure stdlib
on purpose, so it runs anywhere without a virtualenv.

`python serve.py` rather than opening `index.html` directly: the page
fetches its database, and browsers block `fetch()` on `file://`.

## The columns

| Column | Type | Where it comes from |
|---|---|---|
| **Length** | numeric ↑↓ | UniProt. Green on exact, amber within 10%. |
| **Conserved back to** | ordinal ↑↓ | Gene-Ages consensus. The ladder below. |
| **Localization** | multi | UniProt subcellular location, collapsed to 9 buckets. Amber on partial overlap. |
| **Function** | single | Rules over UniProt keywords, EC number and protein name. |
| **Pathway** | multi | Reactome, rolled up to top-level pathways. |
| **Chromosome** | numeric ↑↓ | HGNC cytogenetic location. X→23, Y→24, MT→25 for ordering. |
| **Disease-linked** | boolean | UniProt curated disease annotations with an OMIM anchor. |

### The conservation ladder

This is the column that makes the game worth playing, so it is worth
understanding what it claims.

1. **Universal** — bacteria, archaea and eukaryotes alike
2. **Ancient** — shared with one prokaryotic domain
3. **Eukaryota**
4. **Opisthokonta** — animals and fungi; present in yeast
5. **Eumetazoa** — animals; in flies and worms, not yeast
6. **Vertebrata**
7. **Mammalia**

Gene-Ages ships eight age bins, two of which — "shared with archaea" and
"shared with bacteria" — are **siblings, not rungs**. Neither is deeper
than the other, so ordering them would make the up/down arrow lie. They are
collapsed into "Ancient". What is left is honestly ordinal end to end,
which is the only kind of scale an arrow can hint at.

## Data sources

Everything is fetched by `pipeline/download.py`. Nothing is scraped; every
source has a real bulk endpoint.

| Source | File | Used for |
|---|---|---|
| [UniProt](https://www.uniprot.org/) REST stream | ~20,400 reviewed human entries | length, mass, localization, keywords, EC, disease, synonyms |
| [NCBI Gene](https://www.ncbi.nlm.nih.gov/gene) | `gene2pubmed`, `Homo_sapiens.gene_info` | fame ranking, extra aliases |
| [Reactome](https://reactome.org/) | `UniProt2Reactome_All_Levels` + hierarchy | pathways |
| [HGNC](https://www.genenames.org/) | `hgnc_complete_set` | chromosome |
| [Gene-Ages](https://github.com/marcottelab/Gene-Ages) | `main_HUMAN.csv` | conservation depth |

Optional: `--with-eggnog` adds eggNOG 7 (~920 MB) to fill conservation gaps
Gene-Ages leaves. It is a 2016 snapshot, so newer accessions can be missing.
The column works fine without it; this is a coverage top-up, not a
dependency.

### Why fame ranking matters

Nobody wants to guess `ZNF493`. Every protein is ranked by how many PubMed
papers cite its gene, and the pools are cut from the top of that list:

- **Daily** — 365 proteins, all seven columns present. One year, no repeats.
- **Free play** — 1,000, tolerating one missing column.
- **Hard** — 3,000, tolerating two.

`pipeline/build.py` prints the least famous protein in each tier. If you
don't recognise the one at the bottom of the daily pool, shrink it.

## How the daily answer works

No backend. At build time the daily pool is shuffled with a fixed seed and
the resulting permutation is written into `proteins.json` as `dailyOrder`.
The client computes days since the epoch and indexes into it.

Consequences worth knowing:

- Every player sees the same protein without a server.
- A rebuild does not change tomorrow's answer, as long as
  `DAILY_SHUFFLE_SEED` and `EPOCH` in `build.py` stay put. **Do not change
  them after launch.**
- A determined player can read the answers out of the JSON. Every game in
  this genre has this property. It is not worth engineering around.

## Layout

```
pipeline/
  config.py         URLs, the conservation ladder, classification rules, tiers
  download.py       fetch every source into data/raw/
  parsers.py        one parser per source, all keyed to UniProt accession
  build.py          join, rank by fame, cut tiers, emit the database
  entropy.py        per-column information content — run this after any change
  make_fixture.py   tiny fake raw files for testing without downloading
  test_classify.py  regression tests for the annotation rules
  playtest.py       headless browser run through a real round
web/
  index.html
  style.css
  app.js
  data/proteins.json    generated; committed, since a static host needs it
```

### Tests

```bash
python pipeline/test_classify.py    # annotation rules
python pipeline/playtest.py         # the game itself, in a real browser
```

`test_classify.py` is a list of bugs that actually happened — `actin`
matching "inter**actin**g protein", `antigen` filing TP53 under Immune. When
a protein shows up in-game with a category that makes you wince, add it
there first, then fix the rule.

## Tuning the game

**Columns that don't split the pool are decoration.** `entropy.py` reports
bits per column and flags any where one value dominates:

```
  Column           bits  values                  top value   share
  Conservation     2.31       7               Eumetazoa        31%
  Localization     2.88      24      Nucleus + Cytoplasm       18%
! Disease          0.94       2                      Yes        63%
```

Under ~1 bit means the column is barely earning its slot. Over 80% on one
value means players learn almost nothing from it.

**Classification rules** live in `config.py` as
`(class, keyword patterns, EC prefixes, name patterns)`. Three passes run
over them — name, then EC, then keyword — and first match wins within each,
so list order is priority. Name deliberately beats EC: cytochrome c oxidase
is formally EC 7 translocase, but no biologist calls it a transporter.

Patterns match with a **leading word boundary**, so `actin` won't fire on
"interacting". Keep keyword lists narrow; they run last and a broad term
there hijacks whole classes.

## Deploying

It is a static folder. Push `web/` anywhere:

- **GitHub Pages** — set Pages to serve `/web`, done.
- **Netlify / Vercel** — publish directory `web`, no build command.
- **Anything else** — `rsync -a web/ you@host:/var/www/proteindle/`

The only thing needing a server is a global play counter, which nothing
currently depends on. If you add one, keep it behind a single module so the
game still works when it is unreachable.

## Adding another -dle

The pipeline shape generalises: fetch bulk sources → normalise into ordinal
and categorical columns → rank by a fame proxy → cut tiers → emit JSON. The
web app reads its ladder and columns from the JSON, so a new game is mostly
a new `config.py` and new parsers.

The two things that decide whether a game is fun:

1. **At least two honest ordinal columns.** Arrows carry far more
   information than green/red, but only if the scale is genuinely ordered.
2. **A fame proxy.** Every one of these games dies if the answer is
   something nobody has heard of.

Viruses are the obvious next one — Baltimore classification (I–VII) is a
perfect built-in ordinal, and the answer pool is small enough to curate by
hand.
